# Verbatim

Live transcription for meetings and lectures on iPhone. It runs as a web app in Safari, with no App Store and no build step.

**Open it:** https://rogue030.github.io/verbatim/ in Safari on iPhone.

- **Live transcript** from Apple's speech recognition (the same engine as iPhone dictation). It restarts automatically when Safari stops listening, and notes any gaps.
- **Timestamps and speakers.** Tap a speaker chip when someone else starts talking, and rename speakers at any time. Tap **Mark** to highlight an important moment.
- **History.** Every recording is saved on the device (IndexedDB). You can search, rename, edit lines and record more later.
- **Export** to Word (.docx), plain text, Markdown or a JSON backup, through the iOS share sheet (Save to Files, AirDrop, Mail, Notes) or as a download.
- **Summary and action items** from Claude: meeting notes (decisions, owners, due dates) or study notes (key terms, assignments, review questions). Use your own Anthropic API key, or copy a ready-made prompt into the Claude app and paste the answer back.
- **Startup disclaimer and FAQ.** Every launch shows a notice about consent, accuracy, data handling and warranty, which you must accept to continue. The in-app FAQ (Settings › Privacy, security and FAQ) covers everything below.

## Privacy and data

Verbatim has no server, no account, no analytics and no tracking. Data goes only to these places:

| Data | Where it goes | Who controls it |
|---|---|---|
| Your voice | Apple's speech recognition, which may process it on Apple's servers. Verbatim never saves audio. | Apple ([privacy policy](https://www.apple.com/legal/privacy/)). Turn off *Settings › Privacy & Security › Analytics & Improvements › Improve Siri & Dictation* to stop Apple keeping audio samples. |
| Transcripts, notes, settings | Only the iPhone, in Safari's storage for `rogue030.github.io`. Encrypted by iOS while the phone is locked. | You. Not on GitHub, and not visible to the developer or Anthropic. |
| Summary requests | The transcript goes from the phone directly to Anthropic's API, using your API key. | Anthropic ([privacy policy](https://www.anthropic.com/legal/privacy)). Under Anthropic's commercial terms, API data isn't used for training by default. |
| Claude app route (copy prompt) | Whatever you paste into the Claude app. | Your Claude account's privacy settings. |
| API key | Safari storage on the phone, without extra encryption. Sent only to `api.anthropic.com`. | You. |

## Security

- **Content Security Policy.** The page may only run its own scripts and may only connect to its own origin and `api.anthropic.com`. Injected code couldn't send transcripts or the API key anywhere else.
- **No third-party code at runtime.** The Anthropic SDK is bundled into `vendor/`, so nothing loads from a CDN.
- **Untrusted text is never inserted as HTML.** Transcript text, titles, speaker names and Claude's output are escaped or set as plain text.

Known risks and how to handle them:

1. **Data loss.** Transcripts exist only on the phone. Safari may erase a site's storage after about a week of browsing without a visit, and clearing website data or losing the phone also erases them. Back up regularly (Settings › Back up all).
2. **Shared origin.** Every GitHub Pages site under `rogue030.github.io` shares one storage area. Don't publish other Pages sites from this account, or move Verbatim to its own domain.
3. **Code integrity.** Phones run whatever is on `main`. Protect the GitHub account with two-factor authentication, and remove app access you no longer need at https://github.com/settings/installations.
4. **API key.** Use a dedicated key with a monthly spending limit in the Anthropic Console. Revoke it if the phone is lost.

## Recording and consent

This is general information, not legal advice. A saved live transcript generally counts as recording a conversation. Some US states (including California, Florida, Illinois, Pennsylvania and Washington) and many countries require everyone's consent. Schools and employers often have their own rules, and in the EU and UK transcripts are personal data under the GDPR. Users are responsible for complying, and the startup disclaimer says so.

## Hosting

Safari only allows the microphone on HTTPS pages, so serve this folder from any static host. It's live on GitHub Pages from `main`. There is no build step; the files are served as they are.

To try it locally on a computer:

```sh
python3 -m http.server 8000   # then open http://localhost:8000 in Chrome or Safari
```
